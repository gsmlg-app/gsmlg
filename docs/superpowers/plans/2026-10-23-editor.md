# Editor Implementation Plan

> **For agentic workers:** Use subagent-driven-development to implement independent tasks in the same session. Respect the ownership below; preserve other workers' edits.

**Goal:** Add the approved DuskMoon Editor and operating-system file-open integration.

**Architecture:** Shared file service and Cubit feed one Editor page. Native bridges preserve original document identity; application-level delivery queues route external files after startup.

**Tech Stack:** Flutter, Dart workspace, flutter_bloc, duskmoon_ui 2.2.3, file_selector, Kotlin / SAF, Swift / UIDocumentPicker and Cocoa.

## Shared Dart contract

`EditorFile` contains `uri`, `name`, `writable`, `bytes`. `EditorFileService` exposes `initialize(List<String> arguments)`, broadcast `openRequests`, `hasPendingFiles`, `takePendingFile()`, `pickFile()`, `readFile(String uri)`, `writeFile(EditorFile file, Uint8List bytes)`, `saveFileAs(String name, Uint8List bytes)`, `dispose()`. A fake can override methods.

`EditorCubit(EditorFileService)` exposes `updateText(String)`, `newDocument()`, `openFile([String? uri]) -> Future<bool>`, `save() -> Future<bool>`, `saveAs() -> Future<bool>`, `discardChanges()`, `clearError()`. `EditorState` contains `text`, `savedText`, nullable `file`, `busy`, nullable `failure`; getters `isDirty` and `name` (default `untitled.txt`). `EditorFailure` values: `unsupportedEncoding`, `binaryFile`, `tooLarge`, `readFailed`, `writeFailed`. File operations catch expected failures, retain prior document on error, and keep dirty state until a successful save. UI owns permission to discard before calling new/open.

The file service is registered in MainProvider; EditorCubit is provided in MultiBlocProvider. App initializes the service, listens to openRequests and navigates to Editor while the screen drains pending URIs sequentially. A route onExit dialog protects all navigation including the adaptive tab controls.

## Verification commands

```sh
flutter test app_lib/editor/test app_bloc/editor/test test/screens/toolbox/editor test/screens/toolbox/toolbox_screen_test.dart test/screens/app/splash_screen_test.dart
dart analyze app_lib/editor app_bloc/editor lib/screens/toolbox/editor lib/screens/toolbox/toolbox_routes.dart lib/screens/toolbox/toolbox_screen.dart lib/app.dart lib/main.dart lib/screens/app/splash_screen.dart app_lib/provider/lib/src/main.dart
flutter build macos --debug
flutter build apk --debug
flutter build ios --simulator --debug
git diff --check
```

Run builds sequentially because Flutter shares native build state. Use test files that exist after each component lands; run baseline Toolbox/Splash tests before source edits. Windows/Linux runtime acceptance is unavailable on the macOS host and must remain explicitly unverified.
