## 目标与边界

每个会话独立拥有生成状态、输入草稿与错误。切换会话、进入历史页或离开聊天页，不取消正在执行的任务。远程会话可以同时运行，本地会话共用单一推理执行槽并按提交顺序排队。同一会话最多有一个待处理轮次。

本次不增加系统后台服务、进程终止后的任务自动重试、同一会话多轮发送队列，也不调整现有导航结构。应用在前台切换页面时任务继续，不承诺 Android 挂起或终止进程后继续执行。

## 状态与资源所有权

保留应用级 ChatBloc 协调会话，分别维护以下内容：

- selectedConversationId：当前显示的会话。
- 按 conversationId 保存的不可变会话状态：消息、生成阶段、当前回复 ID、错误、草稿和本轮配置摘要。
- 按 conversationId 保存的内部任务资源：流订阅、取消句柄、计时器、单调计时器、配置快照和任务标识。资源句柄不进入 Equatable 状态。
- 历史摘要列表：与会话状态按 ID 合成，供列表显示运行状态及预览。
- 本地 FIFO 队列与执行槽：仅负责本地资源调度，不阻塞远程任务。

会话加载状态与生成阶段分开。生成阶段为 idle、queued、running、stopped、failed；running 可以显示等待首个输出、思考、生成文本、调用工具等活动。只有实际执行中的任务计入 Running，queued 单独统计。

所有异步事件携带 conversationId 和 runId；每次重试或重新生成分配新 runId。结束、停止或删除后，过期事件必须被忽略。工具执行结果也使用相同标识，避免停止后重新启动生成。

## 发送、执行与取消

发送事件明确指定目标会话，进入异步准备前捕获会话 ID。立即占用该会话的轮次，防止双击或等待配置期间重复发送。模型、Agent、参数与工具声明在提交时形成快照；凭据通过现有 Vault 路径在执行时解析，不保存到草稿。

远程任务准备完成后独立执行。本地任务进入 FIFO 队列，资源可用后启动；等待时不加载或切换模型。执行阶段需要切换本地模型时，由调度器在取得执行槽后串行完成。执行失败或取消必须释放槽并继续下一项。

停止按钮只作用于指定会话。排队任务可直接取消；运行任务取消流与底层请求，保存已经生成的部分内容，再进入 stopped。完成与取消按任务终态仲裁，不能重复落库或覆盖其他会话。

当前 RemoteLlmRepository.stopGeneration 会关闭共享 HTTP client。实施时需要改成任务级取消，例如任务独享请求 client 及其释放句柄，确保停止 A 不影响 B 或模型列表请求。不能仅移除流监听就声称底层请求已停止。

TTFT、总耗时、输出速度与上下文统计均按任务计算，沿用现有指标语义。排队时长不计入推理耗时；历史 TTFT 为空时保持为空。

后台会话完成或失败只更新该会话及列表摘要，不修改当前选中会话的状态或输入。结束路径及时释放任务资源，只保留展示所需状态。

## 草稿与会话配置

草稿按会话保存文本、光标选区和待发送附件，保存到应用级内存状态；切换会话或离开再返回页面时恢复。首版不承诺进程重启后恢复草稿，避免引入数据库迁移与附件持久化。

新建会话即分配真实 ID，避免所有未发送的新会话共享一个空 ID。每个会话保存自己的 Agent/模型选择与思考选项，首次使用继承全局默认；不改变全局设置保存与 Agent 激活的既有语义。

提交被接受后仅清除该会话提交的草稿。准备失败时保留草稿与附件供重试。运行期间允许编辑下一条文字草稿，但不允许在该会话再次发送；完成后恢复发送。录音不能跨会话继续，录音期间切换会话需要先结束录音并将附件归入原会话。

输入组件根据会话 ID 绑定草稿；异步文件选择、录音回调需要捕获原会话 ID，不能将附件加入后来选中的会话。Duo 输入、发送与停止同样携带会话 ID，并验证当前绑定关系，避免延迟消息串会话。

## 会话列表与页面交互

保留现有列表行结构和选中高亮。每行通过 conversationId 获取状态：

| 阶段 | 行内显示 |
| --- | --- |
| running | 小型转圈图标、Running、当前活动和耗时 |
| queued | 排队中及队列位置 |
| failed | 失败提示；进入会话查看具体错误并重试 |
| stopped | 已停止 |
| idle 且有草稿 | 草稿标记 |
| idle 且无草稿 | 最近消息与时间 |

草稿标记可以与 Running 同时出现，主状态优先显示生成阶段。未选中的会话在本轮完成后显示“新回复”，打开该会话清除；当前正在查看的会话完成时不显示此标记。

列表顶部显示“运行中 N”，点击筛选运行会话；无运行任务时隐藏入口。排队会话仍在完整列表展示。列表按正常会话活动时间排序，流 token 和计时更新不改变排序。摘要按需更新，避免每个 token 重建整张列表。

聊天页的停止、编辑、重新生成与发送可用性只由当前会话决定。后台会话失败不在当前会话弹出错误。顶部模型名来自当前会话配置或本轮快照，不能因其他会话修改选择而跳变。

## 删除、清空与恢复

删除运行或排队中的会话时，确认文案明确包含“停止并删除”。协调器先失效任务标识、取消任务并等待受控清理，再删除存储与草稿。清空消息遵循同样顺序。批量删除涵盖其对应任务，不能遗留回调重新写入已删除会话。

应用启动后不从旧消息的 isStreaming 推断任务仍在执行；不存在实际任务的未完成回复显示为已中断，并保留已落库内容。不会自动重发请求或工具调用。首版不增加逐 token 写库，进程终止前未保存的片段仍可能丢失。

## 方案比较

1. 只隔离页面状态：改动小，但不能支持多会话运行，无法满足已确认的并发策略。
2. 每个会话建立完整 ChatBloc：隔离直接，但共享本地模型、历史列表与资源释放仍需额外协调。
3. 应用级协调器维护会话状态和任务：推荐。复用现有注入方式，明确区分页面选择、会话状态和推理资源。

## 验收

- A 运行时进入 B，B 不显示 A 的停止按钮或错误，且可以编辑和发送。
- 两个远程会话输出、思考、工具调用和计时分别归属各自会话；停止 A 不影响 B。
- 同一会话连续点击发送只产生一个轮次；等待配置期间切换会话不改变发送目标。
- 两个本地会话按提交顺序执行；取消排队任务不影响运行任务，运行失败后下一项继续。
- A/B 文本、光标和附件切换后恢复；异步附件、录音与 Duo 回调不会串会话。
- 后台会话完成或失败时列表立即更新，Running 数量正确，列表不随 token 跳动。
- 重新生成、停止、删除与迟到的 token/工具结果竞争时，不出现串流、复活或重复落库。
- 应用重启后不显示没有对应实际任务的 Running，不自动重放工具调用。
- 保留现有消息导航、错误展示和 TTFT 回归覆盖；新增任务取消隔离、本地 FIFO、草稿与列表 widget 覆盖。
- 在指定 Pixel Fold 上验证切换、双远程运行、单任务停止、列表提示以及展开/折叠布局。设备验证与单元测试结果分别报告。
